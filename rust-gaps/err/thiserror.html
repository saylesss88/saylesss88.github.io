Understanding thiserror by Building It Yourself

This chapter builds a small config loader, load_port, three times:

  1. With String errors and map_err everywhere
  2. With a hand-written error enum: Display, Error, and From impls
  3. With #[derive(thiserror::Error)]

After that, we write a stripped-down version of the derive macro so you can see there’s nothing magic going on.

Writing the impls by hand first shows you exactly what thiserror writes for you. It’s code you could write yourself; you just don’t want to write it for every variant of every error type you ever make.

What problem does thiserror solve?

In Rust, “being an error” is a contract made of a few separate pieces:

PieceTraitWho uses it
A debug representationDebugunwrap(), {:?}, fn main() -> Result<..>
A human-readable messageDisplay{}, logs, error output for users
A link to the underlying causeError::source()error reporters walking the chain
Automatic conversion for ?From<E>the ? operator

std::error::Error itself is almost empty. It requires Debug + Display and gives you an optional source() method. Everything else is boilerplate you write around it, and that boilerplate is what thiserror generates.

Our running example reads a file like this:

port = 8080

and returns the port as a u16. Several things can go wrong:

  • the file can’t be read (io::Error)
  • there’s no port line
  • the line has no =
  • the value isn’t a valid u16 (ParseIntError)

Pass 1: String errors

The quickest thing that works is turning every failure into a String:

use std::fs;

fn load_port(path: &str) -> Result<u16, String> {
    let text = fs::read_to_string(path)
        .map_err(|e| format!("failed to read {path}: {e}"))?;

    let line = text
        .lines()
        .find(|l| l.trim_start().starts_with("port"))
        .ok_or_else(|| "missing `port` key".to_string())?;

    let value = line
        .split_once('=')
        .map(|(_, v)| v.trim())
        .ok_or_else(|| format!("malformed line: {line}"))?;

    value
        .parse::<u16>()
        .map_err(|e| format!("invalid port {value:?}: {e}"))
}

fn main() {
    let path = std::env::args().nth(1).unwrap_or_else(|| "app.conf".into());
    match load_port(&path) {
        Ok(port) => println!("listening on {port}"),
        Err(e) => {
            eprintln!("error: {e}");
            std::process::exit(1);
        }
    }
}
$ portcfg bad.conf
error: invalid port "80x": invalid digit found in string

For a tiny binary this is honestly fine. The problems show up once someone else calls load_port:

  • The caller can’t match on the failure. Say the caller wants to fall back to port 8080 when the key is missing. The only way to do that is to compare strings, and that breaks as soon as someone changes the wording.
  • The cause chain is gone. The original io::Error got flattened into text. The caller can’t check e.kind() == NotFound.
  • Every ? needs a map_err. String has no From<io::Error>, so you have to convert by hand at every call site.

Box<dyn Error> fixes the third problem, since ? converts into it automatically. But the caller still can’t match on a variant without downcasting.

Pass 2: A hand-written error enum

The idiomatic fix is an enum where each variant is one way things can fail. Variants that wrap a lower-level error keep it as data rather than flattening it into a string:

#![allow(unused)]
fn main() {
use std::{error::Error, fmt, fs, io, num::ParseIntError};

#[derive(Debug)]
pub enum ConfigError {
    Read { path: String, source: io::Error },
    MissingKey(&'static str),
    Malformed { line: String },
    InvalidPort(ParseIntError),
}

// 1. Display: the human-readable message for *this* layer only.
impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            ConfigError::Read { path, .. } => write!(f, "failed to read {path}"),
            ConfigError::MissingKey(key) => write!(f, "missing `{key}` key"),
            ConfigError::Malformed { line } => write!(f, "malformed line: {line}"),
            ConfigError::InvalidPort(_) => write!(f, "invalid port number"),
        }
    }
}

// 2. Error: mostly just `source()`, which links to the underlying cause.
impl Error for ConfigError {
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        match self {
            ConfigError::Read { source, .. } => Some(source),
            ConfigError::InvalidPort(e) => Some(e),
            _ => None,
        }
    }
}

// 3. From: lets `?` convert a ParseIntError into a ConfigError automatically.
impl From<ParseIntError> for ConfigError {
    fn from(e: ParseIntError) -> Self {
        ConfigError::InvalidPort(e)
    }
}
}

The function now returns a real type:

#![allow(unused)]
fn main() {
pub fn load_port(path: &str) -> Result<u16, ConfigError> {
    let text = fs::read_to_string(path).map_err(|source| ConfigError::Read {
        path: path.to_string(),
        source,
    })?;

    let line = text
        .lines()
        .find(|l| l.trim_start().starts_with("port"))
        .ok_or(ConfigError::MissingKey("port"))?;

    let value = line
        .split_once('=')
        .map(|(_, v)| v.trim())
        .ok_or_else(|| ConfigError::Malformed { line: line.to_string() })?;

    Ok(value.parse::<u16>()?) // From<ParseIntError> kicks in here
}
}

And the caller can finally act on specific failures and walk the cause chain:

fn report(e: &dyn Error) {
    eprintln!("error: {e}");
    let mut source = e.source();
    while let Some(cause) = source {
        eprintln!("  caused by: {cause}");
        source = cause.source();
    }
}

fn main() {
    let path = std::env::args().nth(1).unwrap_or_else(|| "app.conf".into());
    match load_port(&path) {
        Ok(port) => println!("listening on {port}"),
        Err(ConfigError::MissingKey(_)) => println!("no port set, using 8080"),
        Err(e) => {
            report(&e);
            std::process::exit(1);
        }
    }
}
$ portcfg missing.conf
error: failed to read missing.conf
  caused by: No such file or directory (os error 2)

$ portcfg nokey.conf
no port set, using 8080

Why Read uses map_err but InvalidPort uses From

This tradeoff matters more than any of the syntax.

  • InvalidPort holds only the source error, so a From impl can build it: ? hands you a ParseIntError and you wrap it. Convenient.
  • Read also holds the path. A From<io::Error> impl has no way to know which path failed, because ? only gives it the io::Error. So you attach that context yourself with map_err.

The cost of convenience is lost context. Our InvalidPort message can’t say which value was bad, because From never saw it. Pass 1 could (invalid port "80x"). If that detail matters, make it a struct variant with a value field and use map_err.

Rule of thumb: use From (and later #[from]) when the source error alone says everything. Use map_err when the caller needs to know what you were doing when it failed.

Notice the Display messages don’t include the source

Read prints failed to read missing.conf, not failed to read missing.conf: No such file or directory. The cause is reached through source(), and the reporter prints it. If you include it in Display too, every error reporter (anyhow, eyre, your own loop) prints it twice:

error: failed to read missing.conf: No such file or directory (os error 2)
  caused by: No such file or directory (os error 2)

Pick one: put the cause in the message or return it from source(), never both. Returning it from source() is the more flexible choice.

That’s about 35 lines of impls for a four-variant enum, and it grows with every variant you add. It’s all mechanical, and that’s exactly what a derive macro is for.

Pass 3: thiserror derive

[dependencies]
thiserror = "2"

use std::{fs, io, num::ParseIntError};
use thiserror::Error;

#[derive(Debug, Error)]
pub enum ConfigError {
    #[error("failed to read {path}")]
    Read { path: String, source: io::Error },

    #[error("missing `{0}` key")]
    MissingKey(&'static str),

    #[error("malformed line: {line}")]
    Malformed { line: String },

    #[error("invalid port number")]
    InvalidPort(#[from] ParseIntError),
}

That’s the whole change. load_port, report, and main stay exactly as they were in Pass 2, and the output is the same byte for byte. The three hand-written impls collapse into attributes:

Pass 2 (by hand)Pass 3 (thiserror)
impl Display with a match#[error("...")] on each variant
source() arm for Reada field named source is picked up automatically
source() arm + impl From for InvalidPort#[from] on the field (implies #[source])
#[derive(Debug)]still yours to write; thiserror doesn’t derive Debug

As with clap’s derive, Pass 2 is arguably clearer to read, since nothing is hidden. Pass 3 wins because it’s hard to get wrong: you can’t forget a source() arm or let a Display arm drift out of sync with the variant.

Attribute reference

AttributeWhereWhat it generates
#[error("msg {field}")]variant or structDisplay arm using inline format args
#[error("{0}")]tuple variantpositional fields by index

#[error(transparent)]single-field variant/structforwards both Display and source() to the inner error
#[source]fieldreturns this field from source()

#[error(transparent)]

Use this when a variant should be “invisible” and look exactly like the error it wraps:

#[derive(Debug, Error)]
pub enum AppError {
    #[error(transparent)]
    Config(#[from] ConfigError),

    #[error("server failed to start")]
    Server(#[source] io::Error),
}

AppError::Config prints whatever the inner ConfigError prints and reports the inner error’s source() as its own, so the chain doesn’t gain an extra uninformative layer.

A common use is hiding implementation details behind an opaque public type:

// Public API: callers see `Error`, not your internal enum.
#[derive(Debug, Error)]
#[error(transparent)]
pub struct Error(#[from] ErrorKind);

#[derive(Debug, Error)]
enum ErrorKind {
    // free to change without a semver break
}

Structs work too

Not every error needs variants. If there’s only one way to fail, use a struct:

#[derive(Debug, Error)]
#[error("line {line}: expected `key = value`")]
pub struct ParseError {
    pub line: usize,
}

What thiserror is actually doing: a naive implementation

#[derive(Error)] is a procedural macro. At compile time it gets your enum’s tokens, parses them with syn, and emits new impls with quote. The output is ordinary Rust, essentially what you wrote in Pass 2. Run cargo expand on Pass 3 to see the real expansion.

Here’s a toy version, MiniError, that handles everything our ConfigError needs: #[error("...")] on unit, tuple, and named variants, a field named source, and #[from].

A proc-macro has to live in its own crate:

# mini_error/Cargo.toml
[lib]
proc-macro = true

[dependencies]
proc-macro2 = "1"
quote = "1"
syn = { version = "2", features = ["full"] }

// mini_error/src/lib.rs
use proc_macro::TokenStream;
use quote::{format_ident, quote};
use syn::{parse_macro_input, Data, DeriveInput, Fields, LitStr};

#[proc_macro_derive(MiniError, attributes(error, from))]
pub fn derive_mini_error(input: TokenStream) -> TokenStream {
    let input = parse_macro_input!(input as DeriveInput);
    let name = &input.ident;

    let Data::Enum(data) = &input.data else {
        panic!("MiniError only supports enums");
    };

    let mut display_arms = Vec::new();
    let mut source_arms = Vec::new();
    let mut from_impls = Vec::new();

    for variant in &data.variants {
        let v = &variant.ident;

        // 1. Find `#[error("...")]` and grab the string literal.
        let msg: LitStr = variant
            .attrs
            .iter()
            .find(|a| a.path().is_ident("error"))
            .expect("every variant needs #[error(\"...\")]")
            .parse_args()
            .unwrap();

        match &variant.fields {
            Fields::Unit => {
                display_arms.push(quote! { #name::#v => write!(f, #msg) });
            }

            // Named fields: bind each by name so `{path}` in the
            // message just works via inline format args.
            Fields::Named(fields) => {
                let idents: Vec<_> = fields
                    .named
                    .iter()
                    .map(|f| f.ident.clone().unwrap())
                    .collect();
                display_arms.push(quote! {
                    #[allow(unused_variables)]
                    #name::#v { #(#idents),* } => write!(f, #msg)
                });
                if idents.iter().any(|i| i == "source") {
                    source_arms.push(quote! { #name::#v { source, .. } => Some(source) });
                }
            }

            // Tuple fields: bind as _0, _1, ... and rewrite "{0}" to "{_0}".
            Fields::Unnamed(fields) => {
                let binds: Vec<_> = (0..fields.unnamed.len())
                    .map(|i| format_ident!("_{}", i))
                    .collect();
                let mut text = msg.value();
                for i in 0..binds.len() {
                    text = text.replace(&format!("{{{i}"), &format!("{{_{i}"));
                }
                let rewritten = LitStr::new(&text, msg.span());
                display_arms.push(quote! {
                    #[allow(unused_variables)]
                    #name::#v ( #(#binds),* ) => write!(f, #rewritten)
                });

                // `#[from]` on a single-field variant: generate From + source.
                let first = fields.unnamed.first().unwrap();
                if first.attrs.iter().any(|a| a.path().is_ident("from")) {
                    let ty = &first.ty;
                    from_impls.push(quote! {
                        impl ::core::convert::From<#ty> for #name {
                            fn from(source: #ty) -> Self { #name::#v(source) }
                        }
                    });
                    source_arms.push(quote! { #name::#v(source) => Some(source) });
                }
            }
        }
    }

    quote! {
        impl ::core::fmt::Display for #name {
            fn fmt(&self, f: &mut ::core::fmt::Formatter<'_>) -> ::core::fmt::Result {
                match self { #(#display_arms,)* }
            }
        }

        impl ::std::error::Error for #name {
            fn source(&self) -> Option<&(dyn ::std::error::Error + 'static)> {
                match self {
                    #(#source_arms,)*
                    _ => None,
                }
            }
        }

        #(#from_impls)*
    }
    .into()
}

Replace thiserror::Error with MiniError in Pass 3 and the program behaves identically:

Things to notice:

  • Inline format args do the heavy lifting. The macro binds each field to a local variable with the same name, then passes your string straight to write!. {path} works because a variable named path is in scope. That’s a normal Rust 2021+ feature, not macro magic.
  • Tuple fields need a rename. {0} inside write! means “the first extra argument”, not “field 0”. The real thiserror handles this the same way: it binds fields as _0, _1, and rewrites the format string.
  • #[allow(unused_variables)] exists because a message like "invalid port number" doesn’t mention the field it binds.
  • There’s no runtime component. The macro runs once at compile time, and your binary contains plain impl blocks. thiserror deliberately doesn’t show up in your public API: switching back to hand-written impls is not a breaking change for your users.

What the real crate adds on top of this toy: struct support, #[source] on any field name, #[error(transparent)], extra format arguments, #[backtrace], generics with correct trait bounds, no_std support (2.x), and useful compile errors instead of panic!s.

thiserror vs anyhow: choosing the right tool

These two crates are by the same author (David Tolnay) and are meant to be used together, at different layers:

thiserroranyhow
Gives youYour own concrete error typesOne catch-all anyhow::Error
Callers can match variantsYesNo (only downcast_ref)
Adding contextA field on the variant + map_err.context("reading config")?
Best forLibraries, and modules with an API boundaryBinaries, main, glue code

The usual pattern:

  • Library crates (or a config module inside a binary) define precise errors with thiserror, because their callers need to handle failures.
  • The application’s top level returns anyhow::Result<()>, because at that point the only thing left to do is report the error.
// main.rs of a binary that uses our config module
use anyhow::Context;

fn main() -> anyhow::Result<()> {
    let port = load_port("app.conf").context("loading configuration")?;
    println!("listening on {port}");
    Ok(())
}
Error: loading configuration

Caused by:
    0: failed to read app.conf
    1: No such file or directory (os error 2)

anyhow walked the source() chain that thiserror generated. This is also why keeping the cause out of your Display message matters.

One enum or many?

  • One enum per crate (crate::Error) is simple and common for small libraries. The downside is that every function appears able to return every variant.
  • One enum per operation or module (ConfigError, NetError) tells callers exactly what can go wrong where. Combine them at the top with #[error(transparent)] Config(#[from] ConfigError).

Start with one, and split it when a function’s signature starts lying about what it can return.

Common mistakes

  • Printing the source twice. #[error("read failed: {source}")] plus a source field gives you a duplicated line in every reporter. Choose one.
  • #[from] on two variants with the same type. That would mean two impl From<io::Error> blocks, which conflict. Use map_err for at least one of them, ideally adding context that tells them apart.
  • Reaching for #[from] by reflex. It’s convenient, but ? then quietly drops what you were doing. A bare Io(#[from] io::Error) variant gives you error: No such file or directory, with no hint of which file.
  • Forgetting Debug. thiserror requires it but doesn’t derive it.
  • Using thiserror in main. You can, but if nothing ever matches on the variants, anyhow gets you there with less ceremony.
